 ## 2026-02-23 학습 기록 

  ### 오늘 목표
  - Refactoring Gym Java Step2~Step4를 완료한다.
  - 기능 변경 없이 코드 구조를 개선한다.
  - 테스트 가능한 구조로 리팩토링한다.

  ### 오늘 수행한 내용

  #### Step2 - Early Return
  - 대상: `DeepUmpire`
  - 중첩된 `if-else`를 제거하고 입력 검증을 `validateInput()`으로 분리했다.
  - 예외 조건을 먼저 처리하도록 바꿔 메서드 depth를 줄였다.
  - 결과: 로직 흐름이 단순해지고 읽기 쉬워졌다.

  #### Step3 - Method 
  - 대상: `MassiveUmpire`
  - `playGame()`의 큰 메서드를 역할별 메서드로 분리했다.
  - 분리한 메서드: `validateInput`, `parseDigits`, `parseDigit`, `countStrike`, `countBall`
  - 매직 넘버 `3`을 상수(`DIGIT_COUNT`)로 추출했다.
  - 결과: "입력검증 → 파싱 → 스트라이크 계산 → 볼 계산" 흐름이 명확해졌다.

  #### Step4 - UI 
  - 대상: `ConsoleUmpire`
  - `System.out.println` 의존 로직을 제거하고 `judge()`가 문자열을 반환하도록 변경했다.
  - 출력 포맷 책임을 `formatResult()`로 분리했다.
  - 테스트에서 아래 케이스를 직접 검증할 수 있게 개선했다.
    - 1스트라이크
    - 3스트라이크 + 게임 종료 메시지
    - 낫싱(0볼 0스트라이크)
    - 1볼 1스트라이크
  - 결과: 도메인 로직이 UI와 분리되어 단위 테스트가 쉬워졌다.

  ### 배운 점
  - Early Return은 코드의 들여쓰기뿐 아니라 사고 흐름도 단순하게 만든다.
  - 큰 메서드는 기능 단위로 쪼개면 유지보수와 디버깅이 쉬워진다.
  - 출력/입력 같은 UI 의존 로직을 분리해야 테스트 가능한 코드가 된다.
  - "기능을 바꾸지 않고 구조만 개선"하는 리팩토링 감각이 중요하다.
