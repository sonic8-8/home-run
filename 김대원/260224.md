
## 1. 공공데이터 API는 "문서에 없는 엔드포인트"가 있다

국민참여입법센터 API(`lawmaking.go.kr`)를 쓰면서 깨달은 것:
- **목록 API**(`/rest/ogLmPp.xml`)는 공식 문서에 나와있지만, **상세 API**는 안 나와있었음
- 웹사이트 네트워크 탭을 분석하면 숨겨진 REST 패턴을 발견할 수 있음:
  ```
  /rest/ogLmPp/{id}/{mappingLbicId}/{announceType}.xml
  ```
- 목록 API 응답에 상세 API에 필요한 파라미터(`mappingLbicId`, `announceType`)가 이미 들어있었음

**교훈**: 공공데이터 API 쓸 때, 공식 문서만 보지 말고 **실제 웹사이트의 네트워크 탭**을 꼭 확인하자.

## 2. 웹 스크래핑 vs REST API — 폴백 패턴

웹 스크래핑(Jsoup)은 사이트 구조가 바뀌면 바로 깨짐. 해결 방법:

```
1순위: REST API (구조화된 데이터, 안정적)
2순위: 웹 스크래핑 (API 없거나 실패 시 폴백)
```

이걸 코드로 구현한 패턴:
```java
public Map<String, String> fetchContent(String id, String param1, String param2) {
    // 1순위: REST API
    if (param1 != null && param2 != null) {
        try {
            String result = callRestApi(id, param1, param2);
            if (result != null) return result;  // 성공 → 바로 반환
        } catch (Exception e) {
            log.warn("API 실패 → 크롤링 폴백");
        }
    }
    // 2순위: 크롤링 폴백
    return crawlWebPage(id);
}
```

**교훈**: 외부 데이터 소스는 항상 불안정하다. **1차 방법 + 폴백**을 같이 구현하는 습관을 들이자.

## 3. localStorage 상태관리의 함정 — "삭제했는데 다시 나타남"

알람을 localStorage에서 관리할 때 발생한 버그:

```
사용자가 알람 삭제 → localStorage에서 제거
  ↓
페이지 새로고침
  ↓
서버에서 전체 공지 가져옴 → 삭제한 알람이 다시 추가됨 😱
```

**원인**: "없는 것 = 새로운 것"으로 판단하는 로직의 허점

**해결**: **삭제 기록(dismissedIds)**을 별도로 보관

```javascript
// ❌ 잘못된 로직 — 삭제한 것도 다시 추가됨
const missed = allNotices.filter(n => !existingIds.has(n.id));

// ✅ 올바른 로직 — 삭제 기록 체크
const missed = allNotices.filter(n => 
    !existingIds.has(n.id) && !dismissedIds.has(n.id)
);
```

**교훈**: 클라이언트 상태관리에서 "삭제"는 단순히 목록에서 빼는 게 아니라, **"이 항목을 의도적으로 제거했다"는 기록**을 남겨야 한다. 근본적으로는 서버 DB에서 관리하는 게 맞음.

## 4. 풀스택에서 파라미터 전달 체인을 놓치지 말자

API에 새 파라미터를 추가할 때, **전달 경로의 모든 지점**을 수정해야 함:

```
DB/API 응답 → DTO → Service → Controller → 프론트 API 함수 → 컴포넌트 호출부
```

오늘 `mappingLbicId`/`announceType`를 추가하면서 놓친 것:
- ✅ 백엔드 Service/Controller — 수정함
- ✅ 프론트엔드 `api.js` — 수정함  
- ✅ `LegislationNotice.jsx` (목록 페이지) — 수정함
- ❌ `NoticeDetailModal.jsx` (상세 모달) — **처음에 놓침!**

**교훈**: 새 파라미터 추가 시, `grep`으로 해당 API를 호출하는 **모든 곳**을 찾아서 빠짐없이 수정하자.
```bash
grep -r "getNoticeContent\|fetchNoticeContent" --include="*.jsx" --include="*.js"
```

## 5. `ddl-auto: update`에서 엔티티 설계할 때

JPA `ddl-auto: update`는 엔티티 추가 시 자동으로 테이블을 만들어줌. 향후 회원 기능 확장을 고려한 설계:

```java
@Column(nullable = true)  // ← nullable로 두면 나중에 회원 연결 가능
private Long userId;
```

- 지금은 `null` → 전체 공유
- 나중에 회원 추가 시 → `userId` 채우고 쿼리에 `WHERE user_id = ?` 추가

**교훈**: 확장 가능성이 있는 필드는 **nullable로 미리 잡아두자**. 나중에 컬럼 추가하는 것보다 기존 컬럼에 값 채우는 게 훨씬 쉬움.
