## MISSION 2: 자동차 경주게임 TDD
### 1. 객체 지향 설계 복습 (SRP 중심)
- 테스트 작성 과정에서 클래스 책임이 명확하지 않으면 테스트가 어려워진다는 점 체감
- 한 클래스가 여러 책임을 가지면 테스트 케이스가 복잡해짐을 확인
- SRP가 단순 설계 원칙이 아니라 테스트 용이성과 직접 연결된다는 점 학습
- 생성자에서 유효성 검증을 수행하도록 설계하여 객체의 불변성 강화

### 2. TDD의 효율적인 설계 및 구현
- Red → Green → Refactor 사이클을 작은 단위로 반복
- 콘솔 출력 로직을 직접 테스트하기 어렵다는 문제를 겪으며, 도메인 로직과 출력 책임을 분리해야 테스트가 수월해짐을 경험
- 반환값을 활용하면 assert 기반 검증이 명확해진다는 점 학습
- 검증 테스트(assertEquals, assertTrue, assertFalse)를 통해 의도한 예외와 단순 오류를 구분하는 방법 익힘
