## 1. 일급 컬렉션 복습

객체 지향 설계 방법 중 하나인 일급 컬렉션에 대한 내용을 복습하고 실습한다.

### 일급 컬렉션이란?
**일급 컬렉션**(First-Class Collection)은 단순한 데이터 컬렉션을 하나의 객체로 묶어, 해당 컬렉션과 관련된 모든 로직 검증 행위를 하나의 클래스에서 관리하도록 돕는 설계 방식이다.  
List, Set, Map 같은 컬렉션을 그대로 쓰는 것이 아니라, 그 컬렉션을 하나의 **독립된 객체**로 감싸서 의미와 규칙을 가진 도메인 객체처럼 다루는 것

ex) `List<Car>` 를 데이터 묶음으로 보는 게 아니라, Cars 라는 객체로 만들어서 자동차들의 집합 자체를 하나의 주체로 취급하는 것

### 왜 굳이 사용할까?
**핵심**은, 컬렉션에 대한 규칙과 책임을 한곳에 모으기 위해서 사용한다.  
만약 `List<Car>`를 쓴다면? 중복 이름 검증, 목록 조회 등의 로직이 여기저기 흩어질 수 있음  
Cars 객체를 쓴다면? 자동차에 대한 규칙과 행동을 Cars 안에 모을 수 있음

### 장점
1) 의미가 분명해진다.
- List<Car> 보다 Cars가 훨씬 의미가 명확함 -> 코드 읽는 사람이 의도를 더 쉽게 이해할 수 있음

2) 검증 로직을 한 곳에 모을 수 있다.
- 컬렉션과 관련된 조건을 생성자에서 강제할 수 있음
    - 최대 개수 제한, 최대 글자 수 제한, 중복 여부 체크 등

3) 컬렉션 관련 행동을 객체에 맡길 수 있다.
- cars.moveAll(), cars.findWinners() 등의 행동을 객체에게 넘기면서 책임이 자연스럽게 분리됨

4) 외부에서 컬렉션을 함부로 조작하지 못하게 할 수 있다.
- List를 그대로 꺼내서 수정하면 객체의 불변성이 깨짐
    -> 일급 컬렉션으로 감싸면 외부에서 무분별하게 add, remove하지 못하도록 막을 수 있음

### 정리
일급 컬렉션은 단순 Wrapper Class가 아니다.  
단순 자료 구조가 아니라, 하나의 독립된 객체로 승격시켜 의미/규칙/행동을 부여한 객체이다.
