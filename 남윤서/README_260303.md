# 260303 학습 정리

## 오늘 학습 범위
- Step 1: 이름 짓기 + 매직 넘버 제거
- Step 2: Early Return으로 분기 단순화

## 핵심 개념 정리
- 좋은 이름은 구현이 아니라 의도를 설명한다.
- 숫자 리터럴은 규칙을 숨기므로, 도메인 의미를 가진 상수로 바꾼다.
- 검증 로직은 성공 흐름보다 실패 조건을 먼저 배치하면 읽기가 쉬워진다.

## 적용하면서 정리한 기준
- 메서드/변수 이름만 읽어도 역할이 떠올라야 한다.
- 상수 이름은 "값"이 아니라 "규칙"을 표현해야 한다.
- `if-else` 중첩은 줄이고, 예외는 빠르게 반환한다.

## 코드 읽기 관점에서 얻은 점
- 축약어를 제거하니 코드가 해석 대상이 아니라 설명 문서처럼 읽혔다.
- 매직 넘버를 상수로 올리니 경주 규칙 변경 지점을 한곳에서 관리할 수 있었다.
- Early Return을 적용하니 정상 시나리오가 메서드 하단에 깔끔하게 남았다.

## 다음 학습 연결
- 메서드 이름과 분기 구조를 정리한 뒤에는, 큰 메서드를 역할 단위로 분해하는 연습이 필요하다.
