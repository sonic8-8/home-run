# 260304 학습 정리

## 오늘 학습 범위
- Step 3: 메서드 분리
- Step 4: 관심사 분리(UI와 도메인 분리)

## 핵심 개념 정리
- 큰 메서드는 "검증/변환/실행/출력" 흐름으로 쪼개면 읽기와 수정이 쉬워진다.
- 상위 메서드는 세부 구현보다 진행 순서를 보여주는 오케스트레이터 역할이 적절하다.
- 도메인 로직은 콘솔 출력 같은 I/O에 의존하지 않아야 테스트가 단순해진다.

## 적용하면서 정리한 기준
- 한 메서드는 한 가지 역할만 수행한다.
- 입력 검증 책임은 경계 지점에서 처리하고, 핵심 로직에 섞지 않는다.
- 출력 형식 변경이 도메인 테스트 실패로 이어지지 않게 계층을 분리한다.

## 코드 읽기 관점에서 얻은 점
- 메서드 분리 후 상위 흐름이 "목차"처럼 보여 변경 지점을 빠르게 찾을 수 있었다.
- UI 분리 후 테스트가 문자열 출력이 아니라 값 검증 중심으로 바뀌었다.
- 관심사 분리만으로도 코드 재사용성과 유지보수성이 눈에 띄게 좋아졌다.
