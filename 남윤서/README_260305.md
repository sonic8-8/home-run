# 260305 학습 정리

## 오늘 학습 범위
- Step 5: Value Object
- Step 6: 일급 컬렉션(First Class Collection)
- Step 7: 전략 패턴(Strategy Pattern)

## 핵심 개념 정리
- 원시값 포장은 "값에 규칙을 붙이는 방식"이다.
- 일급 컬렉션은 `List<Car>` 같은 자료구조를 도메인 객체로 감싸, 데이터와 동작을 함께 관리한다.
- 전략 패턴은 변경 가능성이 큰 정책(랜덤 이동 기준)을 인터페이스 뒤로 분리해 교체 가능하게 만든다.

## Value Object 정리
- `CarName`, `Position` 같은 타입으로 의미를 명확히 하면 도메인 표현력이 좋아진다.
- 생성 시점 검증으로 잘못된 상태를 사전에 차단할 수 있다.
- 불변 객체로 다루면 객체 공유 시 부작용 위험이 줄어든다.

## 일급 컬렉션 정리
- `Cars` 객체가 컬렉션을 소유하고, 외부에는 필요한 동작만 노출한다.
- `moveAll()`, `findWinners()` 같은 집합 연산을 컬렉션 내부로 모으면 책임이 자연스럽다.
- 컬렉션 직접 노출을 막으면 외부에서 임의 수정하는 문제를 예방할 수 있다.
- 결과적으로 "차량 목록"이 단순 배열이 아니라 도메인 개념으로 승격된다.

## 전략 패턴 정리
- 이동 조건을 `MovingStrategy`로 추상화하면 랜덤/고정/테스트 전략을 교체할 수 있다.
- 테스트에서는 결정적인 전략을 사용해 항상 같은 결과를 검증할 수 있다.
- 정책 변경이 발생해도 핵심 경주 로직을 수정하지 않아도 된다.

## 객체지향 관점에서 얻은 점
- 규칙은 서비스가 아니라 모델 내부에 있어야 응집도가 높다.
- 도메인 객체가 스스로 상태를 관리할수록 안전한 설계가 된다.
- 테스트 가능성을 고려한 설계가 결국 변경 비용을 낮춘다.

## 마무리 체크리스트
- 원시값이 도메인 규칙을 담아야 하는 자리라면 Value Object를 우선 검토한다.
- 컬렉션이 핵심 개념이라면 일급 컬렉션으로 올려 책임을 명확히 한다.
- 외부 의존(랜덤, 시간, I/O)은 전략 또는 인터페이스로 분리해 테스트 가능하게 만든다.
