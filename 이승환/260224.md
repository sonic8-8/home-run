## 🏋️‍♂️ 스텝별 리팩토링 내용 및 학습 포인트

### 1단계: 이름 짓기 (Naming) & 매직 넘버(Magic Number) 제거
- **명확한 네이밍:** `a`, `b`, `doS`와 같이 의미를 알 수 없던 변수/메서드명을 `numbers`, `target`, `strike`처럼 목적과 행위를 드러내는 이름으로 변경.
- **인덱스 구분:** 중첩 반복문 내에서 `i`, `j` 대신 `guessIndex`, `targetIndex`를 사용하여 혼동 방지.
- **매직 넘버 제거:** `3`과 같이 코드에 하드코딩된 숫자를 `DIGIT_COUNT` 상수로 추출. 코드가 스스로 **"3자리 숫자 야구 게임"**이라는 도메인 의도를 설명하게 함.

### 2단계: Early Return (Guard Clause)
- **보호 구문(Guard Clause) 적용:** 검증 로직(`null` 체크, 크기 검사 등)을 최상단으로 올려 `throw new IllegalArgumentException(...)`으로 처리.
- **코드 평탄화(Flattening):** 예외 상황을 미리 반환(Early Return)시킴으로써, 불필요한 `else` 블록을 제거하고 핵심 로직의 들여쓰기 뎁스(Depth)를 1단계로 평탄화. 이로 인해 코드 가독성이 대폭 향상됨.

### 3단계: 메서드 분리 (Method Separation)
- **단일 책임 원칙:** 한 메서드 내에 뭉쳐있던 `검증 -> 파싱 -> 판독` 로직을 [validateInput](cci:1://file:///c:/Users/SSAFY/Desktop/agile-runner-basecamp/step-baseball/part2-refactoring-gym/java/step3-method-sep/src/main/java/badcode/MassiveUmpire.java:21:4-29:5), [parseInput](cci:1://file:///c:/Users/SSAFY/Desktop/agile-runner-basecamp/step-baseball/part2-refactoring-gym/java/step3-method-sep/src/main/java/badcode/MassiveUmpire.java:31:4-42:5), [countStrike](cci:1://file:///c:/Users/SSAFY/Desktop/agile-runner-basecamp/step-baseball/part2-refactoring-gym/java/step3-method-sep/src/main/java/badcode/MassiveUmpire.java:44:4-53:5), [countBall](cci:1://file:///c:/Users/SSAFY/Desktop/agile-runner-basecamp/step-baseball/part2-refactoring-gym/java/step1-naming/src/main/java/badcode/BadUmpire.java:18:4-28:5)로 잘게 쪼개어 메서드가 "한 가지 일만" 하도록 분리.
- **순수 함수(Pure Function) 도입:** 객체의 멤버 변수(상태)로 데이터를 유지하기보다, 필요한 데이터를 파라미터로 넘기고 반환받는 순수 함수로 구성하여 부작용(Side-effect) 원천 차단.

### 4단계: 관심사 분리 (UI Separation) & 객체 지향(OOP)
- **일급 컬렉션 (First-Class Collection):** `List<Integer>` 타입의 숫자 배열을 [Numbers](cci:2://file:///c:/Users/SSAFY/Desktop/agile-runner-basecamp/step-baseball/part2-refactoring-gym/java/step4-ui-separation/src/main/java/badcode/Numbers.java:7:0-53:1)라는 하나의 도메인 객체로 포장(Wrapping). 생성 시점에서 검증이 완료되므로 언제나 신뢰할 수 있게 됨. `final`을 적용해 불변(Immutable) 객체로 설계.
- **Tell, Don't Ask (묻지 말고 시켜라):** [Umpire](cci:2://file:///c:/Users/SSAFY/Desktop/agile-runner-basecamp/step-baseball/part2-refactoring-gym/java/step1-naming/src/main/java/badcode/BadUmpire.java:4:0-29:1) 데이터(`numbers`)를 꺼내와서 수동으로 비교하는 대신, 데이터를 소유한 [Numbers](cci:2://file:///c:/Users/SSAFY/Desktop/agile-runner-basecamp/step-baseball/part2-refactoring-gym/java/step4-ui-separation/src/main/java/badcode/Numbers.java:7:0-53:1) 객체에게 "결과를 계산해 줘"라고 메시지를 던짐 (`answer.countStrike(guess)`).
- **입출력(I/O) 분리:** 도메인 핵심 로직과 UI(콘솔 입출력 [ConsoleOutputHandler](cci:2://file:///c:/Users/SSAFY/Desktop/agile-runner-basecamp/step-baseball/part2-refactoring-gym/java/step4-ui-separation/src/main/java/badcode/io/ConsoleOutputHandler.java:2:0-42:1))를 완전히 분리. 이로써 외부 I/O 제약 없이 **도메인 룰을 빠르고 완벽하게 단위 테스트(Unit Test)** 할 수 있는 구조를 확보함.
