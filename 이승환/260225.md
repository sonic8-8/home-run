# 2026년 02월 25일 수요일 학습 회고록

## 1. 🏎️ 미션: 자동차 경주

### 📌 배경
자동차 경주 미션을 진행하던 중, `.\gradlew.bat test`를 터미널에서 실행했을 때 프로젝트 빌드는 성공하지만 테스트 실행 단계에서 예외가 발생하며 실패하는 현상을 마주했습니다.

### 🔥 마주친 문제와 해결 과정

#### 1. Gradle 9.0과 JUnit Platform 런처 의존성 문제
**상황:** 콘솔에 다음과 같은 에러가 출력되며 테스트 프레임워크가 아예 시작되지 못했습니다.
> `Failed to load JUnit Platform.  Please ensure that the JUnit Platform is available on the test runtime classpath.`

**원인 파악:** 
이전 버전의 Gradle(8.x 이하)에서는 `test { useJUnitPlatform() }`을 선언하면 내부적으로 알아서 JUnit Platform 실행에 필요한 의존성을 주입해주었습니다. 하지만 최근 릴리즈된 **Gradle 9.0**부터는 이 의존성을 더 이상 자동으로 추가해 주지 않도록 정책이 변경되었습니다. 그 결과 테스트 실행기(Launcher)를 런타임에 찾지 못해 오류가 발생한 것입니다.

**해결 과정:**
`build.gradle` 파일의 `dependencies` 블록에 `junit-platform-launcher`를 명시적으로 추가하여 해결했습니다. (현재 코드는 다시 원복되었지만 로컬 환경설정 트러블슈팅의 핵심이었습니다)

```gradle
dependencies {
    testImplementation 'org.junit.jupiter:junit-jupiter:5.10.2'
    testImplementation 'org.assertj:assertj-core:3.25.3'
    // 명시적으로 추가된 런타임 의존성
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher' 
}
```

**교훈:**
개발 인프라(빌드 도구, 프레임워크)의 메이저 버전이 올라갈 때(Gradle 8 -> 9 등)는 기존에 프레임워크가 암묵적으로 마법처럼 처리해주던 기능들이 명시적 선언으로 바뀔 수 있다는 점을 깨달았습니다. TDD 사이클을 돌리기 전 레드바(Red Bar)를 보는 가장 기초적인 인프라/설정 문제를 빠르게 파악하고 조치할 수 있는 경험이 되었습니다.
