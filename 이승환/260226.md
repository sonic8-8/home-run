# 2026년 02월 26일 목요일 학습 회고록

## 1. 🏎️ 미션: 자동차 경주 결과 정리 및 출력 개선

### 📌 배경
`ConsoleOutputHandler`에서 자동차 경주의 최종 우승자 이름들(`List<String>`)을 넘겨받아 쉼표(`, `)를 기준으로 하나의 문자열로 가공해서 출력해야 하는 상황이었습니다.

### 🔥 마주친 문제와 해결 과정

#### 1. 컬렉션 요소를 하나의 문자열로 합칠 때 `reduce()` 사용의 함정
**상황:** 초기에 함수형 프로그래밍에 익숙해지기 위해 Stream 연산의 기본인 `reduce()`를 활용하여 문자열을 합치려 시도했습니다.

```java
// ❌ 가독성이 떨어지고, String 객체 불변성에 의해 매번 새 메모리 할당 (안티 패턴)
String winnerList = winners.stream()
        .reduce((name1, name2) -> name1 + ", " + name2)
        .orElse("");
```

**원인 파악:**
자바에서 `String`은 **불변(Immutable)** 객체입니다. 따라서 `reduce()` 루프 안에서 `+` 연산자로 문자열을 계속해서 붙이면 매 루프마다 새로운 `String` 객체가 생성되어 메모리에 할당됩니다. 연산이 반복될 경우 불필요한 객체 생성 비용이 커지고 시간 복잡도가 $O(N^2)$ 까지 증가할 수 있다는 단점을 인지하게 되었습니다.

**해결 과정:**
단순히 만들어진 리스트를 하나로 합치는 작업이라면 복잡도를 늘려 `reduce`를 쓸 이유가 없었습니다. 
내부적으로 `StringBuilder`를 사용하여 성능을 최적화해 둔 내장 메서드인 **`String.join()`**이 이런 요구사항을 처리하기에 가장 의도도 잘 표현되고 가독성도 좋다는 걸 배웠습니다.

```java
// ✅ 가독성이 훌륭하며, 내부적으로 StringBuilder를 통해 성능까지 보장된 표준 API
String winnerList = String.join(", ", winners);
System.out.println(winnerList + "가 최종 우승했습니다.");
```

#### 2. 추가 학습 (Stream 파이프라인 안에서는?)
미션을 하며 만약 요소들의 가공(예: 공백 제거 `filter`, 타입 변경 `map`)이 복합적으로 필요해서 `stream()` 파이프라인 처리를 계속해야 하는 상황이라면 어떻게 해야 할까도 살펴봤습니다.
결론적으로 이때는 자바 8에 도입된 **`Collectors.joining()`**을 사용하여 깔끔하게 코드를 작성할 수 있습니다.

```java
// 💡 Stream 연산의 종단부에서 문자열을 묶어야 할 때는 joining 활용!
String winnerList = winners.stream()
        .map(String::trim)
        .collect(Collectors.joining(", "));
```

**교훈:**
동작하는 코드를 작성하는 것을 넘어서 기본 클래스인 **`String`의 근본적 특성(불변성)**을 이해한 상태에서 코딩해야 함을 배웠습니다. 
개발자가 모든 로직(reduce)을 수동으로 제어하기보다 언어가 지원하는 **명확한 의도를 담은 표준 API(String.join 등)**를 활용할 때 유지보수성과 성능 면에서 압도적으로 훌륭한 산출물이 나온다는 점을 다시금 깨달았습니다.
