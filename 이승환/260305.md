# 2026년 03월 05일 목요일 학습 회고록

## 1. 🎯 프로젝트 MVP 스코프 정의 및 기획 구체화

### 📌 배경
'홈런(Home-Run)' 프로젝트의 본격적인 개발에 앞서, 한정된 3주의 개발 기간 동안 실현 가능한 목표를 설정하고 기능을 명확히 분리하는 기획 작업에 집중했습니다.

### 🔥 기획 문서를 작성하며 마주친 고민과 교훈들

#### 1. MVP(Minimum Viable Product)의 단계적 분리
**상황:** 게임 루프와 핀테크 API 연동을 동시에 진행하려고 하니 개발 복잡도가 너무 높아지고, 팀원 간의 작업 의존성이 엉키는 문제가 예상되었습니다.

**교훈:** 개발 단계를 `MVP1(코어 게임 루프가 돌아간다)` → `MVP2(핀테크 API가 붙는다)` → `RELEASE(완성도를 높인다)`로 명확하게 쪼갰습니다. 첫 주에는 실데이터 연동 없이 하드코딩된 데이터만으로도 결제, 정산, 엔딩까지 도달하게 만드는 "시연 가능한 뼈대"를 세우는 것이 안정적이고 빠른 개발의 핵심임을 깨달았습니다.

#### 2. 기능의 명시적 제외(Out of Scope) 설정
**상황:** 회의를 할수록 마이데이터 연동, 세부적인 Markov Chain 경제 사이클, 240개월 장기 캠페인 등 넣고 싶은 기능들이 무한정 늘어났습니다.

**교훈:** 기획 단계에서 가장 중요한 것은 "무엇을 만들지"보다 **"무엇을 (빠르게) 버릴지"** 결정하는 것이었습니다. 우선순위(P0, P1, P2)를 설정해 복잡한 시스템들을 과감하게 MVP2나 추가 목표로 미뤄둠으로써 팀원들이 코어 엔전에만 집중할 수 있는 환경을 만들 수 있었습니다.

## 2. 🎨 Figma를 활용한 와이어프레임 설계 학습
**상황:** 기획된 금융 홈(Part A)과 시뮬레이션 게임(Part B)의 화면 간 이동, UI 레이아웃을 시각적으로 구체화하여 프론트엔드 작업의 혼선을 방지해야 했습니다.

**교훈:** Figma를 다뤄보며 각 화면(좌측 달력 / 우측 스탯 대시보드 등)을 컴포넌트 단위로 분해하고, 유저 플로우에 따른 상태(State) 변화를 시각적으로 매핑해보았습니다. 입력 최소화, 펼침(Advanced) UI 등 공통 UX 원칙을 시각 문서로 정립해두는 것이 이후 개발 과정에서의 소통 비용을 획기적으로 낮춰준다는 것을 체감했습니다.
