# 14th-ai2 학습 내용 정리

## 1. 전체 흐름

- LLM 실습 흐름을 `Pseudo Labeling → LoRA → QLoRA → vLLM` 순으로 단계화.
- 모델 학습 단계를 넘어 데이터 구축, 학습 방식 비교, 추론 서빙 최적화까지 연계.
- 핵심: 데이터-학습-서빙을 하나의 파이프라인으로 통합 검증.

---

## 2. Pseudo Labeling (`skeleton01`)

정답이 없는 데이터에 Teacher 모델 응답을 부여해 Distillation용 데이터셋을 구축하는 단계.

- Upstage Solar API(`openai` 클라이언트) 사용을 통한 Teacher 응답 생성.
- System/User 역할, 제약, 출력 포맷 명시를 통한 응답 품질 안정화 확인.
- Structured output/JSON schema 적용을 통한 결과 형식 일관성 강화 확인.
- 생성 SQL에 reasoning/critique 필드 추가 저장을 통한 사후 품질 점검 체계 구성.

핵심: 학습 이전 라벨 품질과 형식 일관성 확보를 통한 후속 성능 비교 신뢰도 확보.

---

## 3. LoRA 기반 SFT (`skeleton02`)

`datasets`와 CSV(`train/validation`) 연계를 통한 Text-to-SQL 학습 파이프라인 구성.

- `apply_chat_template` 사용을 통한 학습/추론 입력 포맷 일원화.
- PEFT LoRA 적용을 통한 경량 태스크 적응 수행.
- `trl`의 `SFTTrainer` 기반 SFT 학습 루프 구성.
- `PeftModel.from_pretrained(...).merge_and_unload()` 적용을 통한 추론용 LoRA 병합.

`model.generate()`를 `do_sample=False`, `num_beams=1`의 결정론 설정으로 실행해 비교 가능성 확보.

---

## 4. 평가 파이프라인

모델 성능을 텍스트 유사도보다 실행 결과 중심으로 평가.

- 예측 SQL을 `gold.txt`/`predict.txt`(db_id 포함) 포맷으로 저장하는 평가 전처리 구현.
- `test-suite-sql-eval` execution accuracy 기준 적용을 통한 실행 중심 평가 수행.

핵심: SQL 문자열 일치 여부가 아닌 실행 결과 일치 여부 기준으로 성능 판단.

---

## 5. QLoRA (`skeleton03`)

`BitsAndBytesConfig` 기반 4-bit 양자화를 통한 메모리 효율 개선 실습 수행.

- `load_in_4bit`
- `bnb_4bit_use_double_quant`
- `nf4`
- `bfloat16`

위 설정의 의미와 트레이드오프 비교를 통해 적용 조건 확인.
LoRA 대비 QLoRA의 메모리 절감 효과 및 학습 시간 증가 가능성 확인.
시드 고정과 CUDA/NCCL 환경 변수 설정을 통한 재현성/안정성 보강.

---

## 6. vLLM 서빙/벤치마크 (`skeleton04`)

vLLM의 메모리 효율 구조 실습 및 서빙 성능 비교 수행.

- PagedAttention과 KV Cache 동작 원리 확인.
- Runtime LoRA와 Merged Model 비교.
- 지연시간, 토큰 속도, 피크 메모리 기준 벤치마크 수행.
