## 특징

- 변경 이벤트가 매우 분명하게 관리된다. 즉, 실제 어떤 데이터가 변경되었는지가 분명하다.
- 하나의 이력 관리 엔티티에서 다른 엔티티와 통합 이력 관리가 가능하다.
- 변경된 것만 처리하기 때문에 독립적 처리가 가능하다.
- 변화가 발생할 가능성은 매우 낮으며 이력 관리 대상 속성은 매우 많은 경우에 사용하는 것이 유리하다.

---

## 장점

- 특정 속성들에 변화가 집중되는 경우 해당 속성에 대해서만 이력을 관리할 수 있기 때문에 유리하다.

---

## 단점

- 여러 속성에 대한 이력이 필요할 때 많은 머지가 발생한다.
- 이력 관리의 다른 유형들에 비해 향후 사용될 데이터 액세스 쿼리에서 조건 검색이 조금 어렵다.
- 변화가 너무 많은 경우에는 적용이 곤란하다.
