# 📘 TypeScript 타입 좁히기 & 조건부 타입 정리

---

# 1️⃣ 타입 좁히기 (Type Narrowing)

## ✔️ 개념

타입 좁히기란, **넓은 타입을 더 구체적인 타입으로 줄여서** 안전하게 사용하는 기법입니다.

예를 들어:

```ts
function print(value: string | number) {
  if (typeof value === "string") {
    // 여기서는 string으로 좁혀짐
    console.log(value.toUpperCase());
  }
}
```

TypeScript는 조건문을 통해 타입을 자동으로 추론하고 좁혀줍니다.

---

# 2️⃣ 식별할 수 있는 유니온 (Discriminated Union)

## ✔️ 개념

여러 타입을 하나의 유니온으로 묶되,
**공통된 판별자(discriminant)** 를 두어 타입을 안전하게 구분하는 방식입니다.

핵심 조건:

* 모든 타입이 동일한 속성(key)을 가짐
* 해당 속성은 리터럴 타입이어야 함

---

## ✔️ 예시

```ts
type Dog = {
  type: "dog";
  bark(): void;
};

type Cat = {
  type: "cat";
  meow(): void;
};

type Animal = Dog | Cat;
```

여기서 `type`이 판별자 역할을 합니다.

---

## ✔️ 타입 좁히기 적용

```ts
function speak(animal: Animal) {
  if (animal.type === "dog") {
    animal.bark(); // Dog로 좁혀짐
  } else {
    animal.meow(); // Cat으로 좁혀짐
  }
}
```

TypeScript가 자동으로 타입을 구분합니다.

---

## ✔️ 왜 사용하는가?

문제점 (식별자 없을 때):

```ts
if ("bark" in animal) { ... }
```

* 유지보수 어려움
* 구조 변경 시 오류 발생 가능
* 타입 안정성 낮음

👉 판별자를 사용하면 구조가 명확해집니다.

---

# 3️⃣ Exhaustiveness Checking (완전성 검사)

## ✔️ 개념

유니온 타입의 **모든 케이스를 처리했는지 컴파일 단계에서 확인**하는 방법입니다.

새로운 타입이 추가되었는데 처리하지 않으면 오류를 발생시킵니다.

---

## ✔️ never 활용 패턴

```ts
function handle(animal: Animal) {
  switch (animal.type) {
    case "dog":
      return;
    case "cat":
      return;
    default:
      const _exhaustive: never = animal;
      return _exhaustive;
  }
}
```

---

## ✔️ 장점

* 새로운 타입 추가 시 누락 방지
* 런타임 버그 예방
* 리팩토링 안정성 증가

---

# 4️⃣ 조건부 타입 (Conditional Types)

## ✔️ 개념

타입 레벨에서 조건문을 사용하는 기능입니다.

```ts
T extends U ? X : Y
```

뜻:

> T가 U를 확장하면 X, 아니면 Y

---

## ✔️ 기본 예시

```ts
type IsString<T> = T extends string ? true : false;

type A = IsString<string>; // true
type B = IsString<number>; // false
```

---

## ✔️ 조건부 타입을 사용하지 않았을 때 문제

예를 들어:

```ts
type Result<T> = string | number;
```

문제:

* 입력 타입과 결과 타입의 관계가 없음
* 타입 안전성 낮음

---

## ✔️ extends 조건부 타입으로 개선

```ts
type Result<T> = T extends string ? string : number;
```

이제 입력 타입에 따라 결과 타입이 달라집니다.

👉 제네릭 + 조건부 타입 = 강력한 타입 시스템

---

# 5️⃣ 제네릭과 조건부 타입

## ✔️ 제네릭이 필요한 이유

함수를 다양한 타입에서 재사용하기 위해 사용합니다.

```ts
function identity<T>(value: T): T {
  return value;
}
```

---

## ✔️ 조건부 타입과 결합

```ts
type ApiResponse<T> =
  T extends string
    ? { type: "text"; data: string }
    : { type: "json"; data: T };
```

---

# 6️⃣ infer를 이용한 타입 추론

## ✔️ 개념

조건부 타입 내부에서 **타입을 추출**할 때 사용합니다.

```ts
T extends Something<infer U> ? U : never
```

---

## ✔️ 예시 1 — 배열 요소 타입 추출

```ts
type ElementType<T> = T extends (infer U)[] ? U : never;

type A = ElementType<number[]>; // number
```

---

## ✔️ 예시 2 — 함수 반환 타입 추출

```ts
type Return<T> = T extends (...args: any[]) => infer R ? R : never;

type R = Return<() => string>; // string
```

---

## ✔️ infer의 핵심

* 타입을 직접 지정하지 않아도 됨
* 타입 구조에서 자동 추출 가능
* 고급 유틸리티 타입의 핵심 기술

---

# 7️⃣ 전체 핵심 정리

## ✅ 식별할 수 있는 유니온

* 공통 판별자를 사용해 타입 안전하게 분기
* 유지보수성과 가독성 상승

## ✅ Exhaustiveness Checking

* never 활용
* 모든 분기 처리 강제

## ✅ 조건부 타입

* `extends ? :` 형태
* 타입 로직을 작성 가능

## ✅ 제네릭 + 조건부 타입

* 입력 타입 기반 결과 타입 생성
* 강력한 타입 추론

## ✅ infer

* 타입 내부 구조를 추출하는 키워드
* 배열, 함수, Promise 타입 처리 시 자주 사용

---

# 실무에서 중요한 포인트

1. 유니온 타입을 만들면 항상 **판별자 추가 고려**
2. switch 사용 시 never로 완전성 검사 습관화
3. 조건부 타입은 "타입 함수"라고 생각하기
4. infer는 "타입 내부 구조 분해"라고 이해하면 쉬움
