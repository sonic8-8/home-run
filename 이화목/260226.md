# TypeScript 제네릭(Generics)

---

## 1. 제네릭 기본 개념

제네릭 없이는 `any`를 쓰거나, 타입마다 함수를 따로 만들어야 합니다.

```typescript
// ❌ any 사용 - 타입 안전성 없음
function identity(arg: any): any {
  return arg;
}

// ✅ 제네릭 사용 - 타입 안전성 보장
function identity<T>(arg: T): T {
  return arg;
}

const num = identity<number>(42);     // number
const str = identity<string>("hello"); // string
const inferred = identity(true);       // boolean (타입 추론)
```

## 2. 제네릭 함수

### 기본 제네릭 함수

```typescript
// 배열의 첫 번째 요소 반환
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const firstNum = first([1, 2, 3]);       // number | undefined
const firstStr = first(["a", "b", "c"]); // string | undefined
```

### 여러 타입 파라미터

```typescript
// 두 값을 쌍으로 묶기
function pair<K, V>(key: K, value: V): [K, V] {
  return [key, value];
}

const result = pair("name", 25); // [string, number]
```

### 함수 타입에 제네릭 적용

```typescript
type Transformer<T, U> = (input: T) => U;

const numberToString: Transformer<number, string> = (n) => n.toString();
const stringToLength: Transformer<string, number> = (s) => s.length;
```

## 3. 제네릭 인터페이스

```typescript
// 제네릭 인터페이스 정의
interface Repository<T> {
  findById(id: number): T | undefined;
  findAll(): T[];
  save(item: T): void;
  delete(id: number): void;
}

interface User {
  id: number;
  name: string;
}

// 인터페이스를 구현하는 클래스
class UserRepository implements Repository<User> {
  private users: User[] = [];

  findById(id: number): User | undefined {
    return this.users.find((u) => u.id === id);
  }

  findAll(): User[] {
    return this.users;
  }

  save(user: User): void {
    this.users.push(user);
  }

  delete(id: number): void {
    this.users = this.users.filter((u) => u.id !== id);
  }
}
```

### 제네릭 인터페이스 - API 응답 패턴

interface ApiResponse<T> {

## 4. 제네릭 클래스

```typescript
// 제네릭 스택(Stack) 자료구조
class Stack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T | undefined {
    return this.items.pop();
  }

  peek(): T | undefined {
    return this.items[this.items.length - 1];
  }

  get size(): number {
    return this.items.length;
  }

  isEmpty(): boolean {
    return this.items.length === 0;
  }
}

const numberStack = new Stack<number>();
numberStack.push(1);
numberStack.push(2);
console.log(numberStack.pop()); // 2

const stringStack = new Stack<string>();
stringStack.push("hello");
stringStack.push("world");
console.log(stringStack.peek()); // "world"
```

### 제네릭 클래스 - 상태 관리 예시

```typescript
class State<T> {
  private _value: T;
  private listeners: ((value: T) => void)[] = [];

  constructor(initialValue: T) {
    this._value = initialValue;
  }

  get value(): T {
    return this._value;
  }

  set value(newValue: T) {
    this._value = newValue;
    this.listeners.forEach((listener) => listener(newValue));
  }

  subscribe(listener: (value: T) => void): () => void {
    this.listeners.push(listener);
    return () => {
      this.listeners = this.listeners.filter((l) => l !== listener);
    };
  }
}

const counter = new State<number>(0);
const unsubscribe = counter.subscribe((v) => console.log(`Count: ${v}`));

counter.value = 1; // "Count: 1"
counter.value = 2; // "Count: 2"
unsubscribe();     // 구독 해제
```

## 5. 제네릭 제약 조건 (Constraints)

`extends` 키워드로 제네릭 타입에 제약을 걸 수 있습니다.

```typescript
// ❌ 제약 없으면 .length 접근 불가
function getLength<T>(arg: T): number {
  return arg.length; // 오류: T에 length가 있다는 보장 없음
}

// ✅ length 속성을 가진 타입으로 제약
interface Lengthwise {
  length: number;
}

function getLength<T extends Lengthwise>(arg: T): number {
  return arg.length; // ✅ 안전
}

getLength("hello");    // 5
getLength([1, 2, 3]);  // 3
getLength({ length: 10, value: 3 }); // 10
// getLength(42);       // ❌ 오류: number에는 length가 없음
```

### keyof를 활용한 제약

```typescript
// 객체에서 안전하게 프로퍼티 가져오기
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { id: 1, name: "Alice", age: 30 };

const name = getProperty(user, "name"); // string
const age = getProperty(user, "age");   // number
// getProperty(user, "email");           // ❌ 오류: "email"은 키가 아님
```

### 타입 제약 - 클래스 생성자

```typescript
interface Serializable {
  serialize(): string;
}

function createAndLog<T extends Serializable>(
  Constructor: new () => T
): T {
  const instance = new Constructor();
  console.log(instance.serialize());
  return instance;
}
```

## 6. 제네릭 유틸리티 타입 직접 구현

TypeScript 내장 유틸리티 타입을 제네릭으로 직접 만들어보면 이해가 깊어집니다.

```typescript
// Partial<T> - 모든 속성을 선택적으로
type MyPartial<T> = {
  [K in keyof T]?: T[K];
};

// Required<T> - 모든 속성을 필수로
type MyRequired<T> = {
  [K in keyof T]-?: T[K];
};

// Readonly<T> - 모든 속성을 읽기 전용으로
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

// Pick<T, K> - 특정 속성만 선택
type MyPick<T, K extends keyof T> = {
  [P in K]: T[P];
};

// Omit<T, K> - 특정 속성 제외
type MyOmit<T, K extends keyof T> = MyPick<T, Exclude<keyof T, K>>;

// Record<K, V> - 키-값 맵 타입
type MyRecord<K extends keyof any, V> = {
  [P in K]: V;
};
```

### 사용 예시

```typescript
interface Todo {
  id: number;
  title: string;
  completed: boolean;
}

type PartialTodo = MyPartial<Todo>;
// { id?: number; title?: string; completed?: boolean; }

type TodoPreview = MyPick<Todo, "id" | "title">;
// { id: number; title: string; }

type TodoWithoutId = MyOmit<Todo, "id">;
// { title: string; completed: boolean; }
```

## 7. 조건부 타입과 제네릭

```typescript
// T가 string이면 "string type", 아니면 "other type"
type IsString<T> = T extends string ? "string type" : "other type";

type A = IsString<string>; // "string type"
type B = IsString<number>; // "other type"
```

### infer - 타입 추론

```typescript
// 함수의 반환 타입 추출
type ReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never;

function greet(name: string): string {
  return `Hello, ${name}!`;
}

type GreetReturn = ReturnType<typeof greet>; // string

// 배열의 요소 타입 추출
type ArrayElement<T> = T extends (infer E)[] ? E : never;

type NumberArrayElement = ArrayElement<number[]>; // number
type StringArrayElement = ArrayElement<string[]>; // string
```

## 8. 제네릭 - 실전 활용 패턴

### 패턴 1: 제네릭 훅 (React 스타일)

```typescript
function useState<T>(initialValue: T): [T, (newValue: T) => void] {
  let value = initialValue;

  const setValue = (newValue: T) => {
    value = newValue;
  };

  return [value, setValue];
}

const [count, setCount] = useState(0);     // [number, (v: number) => void]
const [name, setName] = useState("Alice"); // [string, (v: string) => void]
```

### 패턴 2: 제네릭 이벤트 시스템

```typescript
type EventMap = {
  login: { userId: string; timestamp: Date };
  logout: { userId: string };
  purchase: { productId: string; amount: number };
};

class EventEmitter<Events extends Record<string, any>> {
  private handlers: Partial<{
    [K in keyof Events]: ((payload: Events[K]) => void)[];
  }> = {};

  on<K extends keyof Events>(
    event: K,
    handler: (payload: Events[K]) => void
  ): void {
    if (!this.handlers[event]) {
      this.handlers[event] = [];
    }
    this.handlers[event]!.push(handler);
  }

  emit<K extends keyof Events>(event: K, payload: Events[K]): void {
    this.handlers[event]?.forEach((handler) => handler(payload));
  }
}

const emitter = new EventEmitter<EventMap>();

emitter.on("login", ({ userId, timestamp }) => {
  console.log(`${userId} logged in at ${timestamp}`);
});

emitter.emit("login", { userId: "user123", timestamp: new Date() }); // ✅
// emitter.emit("login", { userId: 123 }); // ❌ 타입 오류
```

### 패턴 3: 빌더 패턴

```typescript
class QueryBuilder<T> {
  private conditions: string[] = [];
  private limitValue?: number;
  private offsetValue?: number;

  where(condition: string): this {
    this.conditions.push(condition);
    return this;
  }

  limit(n: number): this {
    this.limitValue = n;
    return this;
  }

  offset(n: number): this {
    this.offsetValue = n;
    return this;
  }

  build(): string {
    let query = "SELECT * FROM table";
    if (this.conditions.length > 0) {
      query += ` WHERE ${this.conditions.join(" AND ")}`;
    }
    if (this.limitValue !== undefined) query += ` LIMIT ${this.limitValue}`;
    if (this.offsetValue !== undefined) query += ` OFFSET ${this.offsetValue}`;
    return query;
  }
}

const query = new QueryBuilder<User>()
  .where("age > 18")
  .where("active = true")
  .limit(10)
  .offset(20)
  .build();

// "SELECT * FROM table WHERE age > 18 AND active = true LIMIT 10 OFFSET 20"
```

## 9. 제네릭 기본값

```typescript
// 제네릭에 기본 타입 지정
interface Container<T = string> {
  value: T;
}

const strContainer: Container = { value: "hello" };      // T = string (기본값)
const numContainer: Container<number> = { value: 42 };   // T = number

// 함수에서도 기본값 사용 가능
function createArray<T = string>(length: number, fill: T): T[] {
  return Array(length).fill(fill);
}

const strings = createArray(3, "x");   // string[]
const numbers = createArray(3, 0);     // number[]
```

## 10. 정리 - 언제 제네릭을 사용할까?

| 상황 | 사용 이유 |
|------|-----------|
| 다양한 타입에서 동일한 로직 | 코드 재사용, `any` 대체 |
| 컬렉션/자료구조 구현 | 타입 안전한 Stack, Queue, Map 등 |
| API 응답 타입 처리 | 응답 구조는 같고 데이터 타입만 다를 때 |
| 유틸리티/헬퍼 함수 | 입력 타입에 따라 출력 타입이 결정될 때 |
| 콜백/고차 함수 | 함수 합성, 파이프라인 구성 |

> 💡 **핵심 원칙**: `any`를 쓰고 싶을 때 제네릭을 먼저 고려하세요.  
> 타입 안전성을 유지하면서도 유연한 코드를 작성할 수 있습니다.
