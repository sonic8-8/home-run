# TypeScript 옵셔널 매개변수/속성 (Optional Parameters/Properties)

## 1. 개요

TypeScript에서 **옵셔널(Optional)** 이란, 값이 있을 수도 있고 없을 수도 있는 선택적인 요소를 의미합니다.  
`?` 기호를 사용해 표시하며, 해당 매개변수나 속성은 `타입 | undefined`로 취급됩니다.

```ts
// ? 를 붙이면 선택적(optional)으로 만들 수 있습니다.
function greet(name: string, greeting?: string) { ... }
```

---

## 2. 옵셔널 매개변수 (Optional Parameters)

### 기본 문법

함수의 매개변수 이름 뒤에 `?`를 붙여 선언합니다.

```ts
function greet(name: string, greeting?: string): string {
  if (greeting) {
    return `${greeting}, ${name}!`;
  }
  return `Hello, ${name}!`;
}

greet("Alice");              // ✅ "Hello, Alice!"
greet("Alice", "Hi");        // ✅ "Hi, Alice!"
greet("Alice", undefined);   // ✅ "Hello, Alice!" (undefined 명시도 허용)
```

### 타입 추론

옵셔널 매개변수의 타입은 내부적으로 `string | undefined`로 처리됩니다.

```ts
function showAge(age?: number): void {
  // age의 타입은 number | undefined
  console.log(age);           // number | undefined
  console.log(age?.toFixed()); // 옵셔널 체이닝으로 안전하게 접근
}
```

### ⚠️ 위치 규칙: 옵셔널 매개변수는 반드시 뒤에 위치해야 합니다

```ts
// ❌ 오류: 필수 매개변수가 옵셔널 뒤에 올 수 없음
function invalid(a?: string, b: string) { ... }

// ✅ 올바른 순서
function valid(a: string, b?: string) { ... }
```

### 기본값(Default Value)과의 차이

기본값을 지정하면 `undefined`가 전달될 때 기본값이 사용됩니다.  
단, 기본값이 있는 매개변수는 `?`를 붙이지 않아도 선택적으로 동작합니다.

```ts
// 옵셔널 매개변수
function optionalParam(name?: string): string {
  return `Hello, ${name}`; // name이 undefined이면 "Hello, undefined"
}

// 기본값 매개변수 (더 안전!)
function defaultParam(name: string = "Guest"): string {
  return `Hello, ${name}`; // name이 없으면 "Hello, Guest"
}

optionalParam();    // "Hello, undefined"
defaultParam();     // "Hello, Guest"
```

| 구분 | 옵셔널 (`?`) | 기본값 (`= value`) |
|------|------------|-----------------|
| 생략 가능 여부 | ✅ | ✅ |
| 타입 | `T \| undefined` | `T` |
| undefined 전달 시 | `undefined` 그대로 | 기본값으로 대체 |
| `?` 표기 필요 | ✅ | ❌ (자동 선택적) |

## 3. 옵셔널 속성 (Optional Properties)

### 인터페이스(Interface)에서의 옵셔널 속성

```ts
interface User {
  id: number;
  name: string;
  email?: string;  // 선택적 속성
  age?: number;    // 선택적 속성
}

// ✅ email, age 없어도 됨
const user1: User = { id: 1, name: "Alice" };

// ✅ 일부만 포함해도 됨
const user2: User = { id: 2, name: "Bob", email: "bob@example.com" };

// ✅ 모두 포함해도 됨
const user3: User = { id: 3, name: "Carol", email: "carol@example.com", age: 30 };
```

### 타입 별칭(Type Alias)에서의 옵셔널 속성

```ts
type Product = {
  id: number;
  name: string;
  description?: string;
  price?: number;
};

const item: Product = { id: 101, name: "Laptop" }; // ✅
```

### 클래스(Class)에서의 옵셔널 속성

```ts
class Profile {
  name: string;
  bio?: string;   // 선택적 속성

  constructor(name: string, bio?: string) {
    this.name = name;
    this.bio = bio;
  }

  display(): string {
    return this.bio
      ? `${this.name}: ${this.bio}`
      : `${this.name}`;
  }
}

const p1 = new Profile("Alice");              // ✅
const p2 = new Profile("Bob", "Developer");   // ✅
```

## 4. 옵셔널 속성 접근 패턴

### 4-1. 조건문으로 검사

```ts
interface Config {
  host: string;
  port?: number;
}

function connect(config: Config) {
  const port = config.port !== undefined ? config.port : 3000;
  console.log(`Connecting to ${config.host}:${port}`);
}
```

### 4-2. Nullish Coalescing (`??`)

```ts
function connect(config: Config) {
  const port = config.port ?? 3000; // undefined이면 3000 사용
  console.log(`Connecting to ${config.host}:${port}`);
}
```

### 4-3. 옵셔널 체이닝 (`?.`)

중첩 객체에서 안전하게 접근할 때 사용합니다.

```ts
interface Address {
  city?: string;
  zipCode?: string;
}

interface Person {
  name: string;
  address?: Address;
}

const person: Person = { name: "Alice" };

// ❌ 위험: address가 undefined이면 런타임 오류
// console.log(person.address.city);

// ✅ 안전: undefined이면 undefined 반환
console.log(person.address?.city);      // undefined
console.log(person.address?.zipCode);   // undefined
```

### 4-4. 타입 가드(Type Guard)로 좁히기

```ts
interface Button {
  label: string;
  onClick?: () => void;
}

function handleButton(btn: Button) {
  // onClick이 존재하는 경우에만 호출
  if (typeof btn.onClick === "function") {
    btn.onClick(); // 여기서는 () => void로 타입이 좁혀짐
  }
}
```

## 5. 실전 활용 예시

### API 요청 옵션 객체

```ts
interface FetchOptions {
  method?: "GET" | "POST" | "PUT" | "DELETE";
  headers?: Record<string, string>;
  body?: string;
  timeout?: number;
}

async function fetchData(url: string, options?: FetchOptions) {
  const method = options?.method ?? "GET";
  const timeout = options?.timeout ?? 5000;

  console.log(`[${method}] ${url} (timeout: ${timeout}ms)`);
  // ... 실제 fetch 로직
}

fetchData("https://api.example.com/users");
fetchData("https://api.example.com/users", { method: "POST", body: '{"name":"Alice"}' });
```

### 컴포넌트 Props (React 패턴)

```ts
interface ButtonProps {
  label: string;
  variant?: "primary" | "secondary" | "danger";
  disabled?: boolean;
  onClick?: () => void;
}

function Button({ label, variant = "primary", disabled = false, onClick }: ButtonProps) {
  return `<button class="${variant}" ${disabled ? "disabled" : ""} >${label}</button>`;
}
```

### 부분 업데이트 패턴 (Partial)

```ts
interface User {
  id: number;
  name: string;
  email: string;
  age: number;
}

// Partial<T>: 모든 속성을 옵셔널로 만드는 유틸리티 타입
function updateUser(id: number, updates: Partial<User>): void {
  console.log(`Updating user ${id}:`, updates);
}

updateUser(1, { name: "Alice" });           // ✅ 이름만 변경
updateUser(2, { email: "new@email.com" });  // ✅ 이메일만 변경
updateUser(3, { age: 25, name: "Carol" });  // ✅ 여러 필드 변경
```

## 6. 유틸리티 타입과의 연계

### `Partial<T>` — 모든 속성을 옵셔널로

```ts
interface Todo {
  title: string;
  description: string;
  completed: boolean;
}

type PartialTodo = Partial<Todo>;
// { title?: string; description?: string; completed?: boolean; }

const draft: PartialTodo = { title: "Buy groceries" }; // ✅
```

### `Required<T>` — 모든 옵셔널을 필수로

```ts
interface Config {
  host?: string;
  port?: number;
}

type StrictConfig = Required<Config>;
// { host: string; port: number; }

const cfg: StrictConfig = { host: "localhost", port: 8080 }; // ✅ 모두 필수
```

### `Pick<T, K>` / `Omit<T, K>` — 선택적 조합

```ts
interface User {
  id: number;
  name: string;
  email?: string;
  age?: number;
}

type PublicUser = Pick<User, "id" | "name">;
// { id: number; name: string; }

type UserWithoutId = Omit<User, "id">;
// { name: string; email?: string; age?: number; }
```

## 7. 자주 하는 실수와 주의사항

### ❌ 실수 1: 옵셔널인데 바로 사용하기

```ts
interface Config {
  port?: number;
}

function start(config: Config) {
  // ❌ 오류: config.port는 number | undefined
  const doubled = config.port * 2;

  // ✅ 안전하게 처리
  const port = config.port ?? 3000;
  const doubled2 = port * 2;
}
```

### ❌ 실수 2: undefined와 null 혼동

```ts
interface Data {
  value?: string; // string | undefined (null은 아님!)
}

const d: Data = { value: null }; // ❌ 오류! null은 undefined가 아님

// null도 허용하려면 명시적으로
interface DataWithNull {
  value?: string | null;
}
```

### ❌ 실수 3: 빈 문자열을 truthy 체크로 옵셔널 처리

```ts
interface Options {
  label?: string;
}

function render(opts: Options) {
  // ❌ label이 "" (빈 문자열)이면 조건이 false가 됨
  const label = opts.label || "Default";

  // ✅ undefined만 걸러내려면 ?? 사용
  const label2 = opts.label ?? "Default";
}
```

## 8. 요약 정리

| 구분 | 문법 | 설명 |
|------|------|------|
| 옵셔널 매개변수 | `param?: Type` | 함수 호출 시 생략 가능 |
| 옵셔널 속성 | `prop?: Type` | 객체 생성 시 생략 가능 |
| 내부 타입 | `Type \| undefined` | 항상 undefined 가능성 존재 |
| 안전한 접근 | `obj?.prop` | 옵셔널 체이닝 |
| 기본값 처리 | `value ?? default` | Nullish Coalescing |
| 전체 옵셔널화 | `Partial<T>` | 유틸리티 타입 |
| 전체 필수화 | `Required<T>` | 유틸리티 타입 |

> **핵심 원칙**: 옵셔널 값은 사용하기 전에 반드시 `undefined` 여부를 확인하세요.  
> `?.`, `??`, 조건문, 타입 가드를 적극 활용하여 안전한 코드를 작성하세요.
